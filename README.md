# Jogajog Emergency

Two connected products:

1. **Physical QR-sticker store** — customers browse physical products (bike, car, luggage,
   helmet stickers) and buy them with a **one-time payment**. No subscription required.
2. **SaaS emergency-profile platform** — the account, the emergency profile, the privacy
   controls, and the public page a finder or first responder lands on when they scan a tag.

A tag is *purchased*, not generated by the customer. QR codes come from a platform-controlled
inventory an admin mints in batches.

## Stack

Next.js 16 (App Router; the proxy file is `src/proxy.ts`) + PostgreSQL + Prisma + Auth.js
(credentials, JWT sessions) + Tailwind v4 + `sharp` (image processing). Payments run through a
`DEMO` provider stub pending a real Bangladesh gateway (SSLCommerz / bKash). Tests: Vitest
(`npm test`) — security-critical pure logic only.

## Local setup

1. PostgreSQL 14+ with `DATABASE_URL` set in `.env` (copy `.env.example`). `docker compose up
   -d postgres` spins one up with the wired-in credentials.
2. `npm install`
3. `npm run db:migrate` (or `npx prisma migrate deploy` for a non-interactive apply)
4. `npm run db:seed` — subscription plans (dormant), an admin (`admin@jogajog.app` /
   `ChangeMe123!` — **change this immediately**), and four `ACTIVE` sticker products with
   placeholder images.
5. `npm run dev`

If you are migrating a database that already has pre-redesign data, run
`npm run db:backfill` **after** migration M1 (`add_store_profile_privacy_media`) and before
M2 — it assigns a "Legacy Tag" product to existing tags, generates claim codes, and creates
one emergency profile per tag-owning user. The script is idempotent and safe to re-run.

- `src/lib/` — `public-profile.ts` (the single source of truth for what the scan page may

  `cart.ts`, `nav.ts` (safe `?next=`), `premium.ts`, plus the Prisma client, Auth.js config,
  QR + short-code generation, IP hashing, rate limiter, notification stub, zod schemas.

## Tag lifecycle

```
UNASSIGNED  ──(admin batch generation)         raw inventory, no owner
ALLOCATED   ──(checkout reserves N of a product)   attached to a paid order, not yet active
ACTIVE      ──(order paid, or /claim by code)      owned and live
LOST / DEACTIVATED ──(owner, from the dashboard)
```

Checkout allocates inventory tags with `SELECT … FOR UPDATE SKIP LOCKED` inside one
transaction, records an `ORDER` payment, marks the order `PAID`, and flips the tags to the
buyer as `ACTIVE`. Each tag also carries a printed `claimCode` for attaching a sticker bought
offline, gifted, or replaced via `/claim`. An admin can return a tag to inventory, which
scrubs the owner, the order link, and the private label. Deleting a user detaches their tags
(`onDelete: SetNull`) rather than destroying them.

## Privacy

The public scan page renders **only** the DTO from `src/lib/public-profile.ts`. A field
appears only if its per-field visibility flag on the owner's `EmergencyProfile` is set. The
owner's real account name, account phone, and non-public medical data never enter the DTO —
not as a value, not as a key. Presets (Minimal / Standard / Full) are one-click ways to set
the flags; any manual change makes the profile "Custom". Default for a new profile is
Standard: name + photo + emergency message + emergency contacts public; medical + phone
private.

## Privacy & abuse-prevention notes

- Raw finder IPs are never stored; `src/lib/hash.ts` salts and hashes them before a
  `ScanEvent`.
- `src/lib/rate-limit.ts` rate-limits scan views, relay messages, abuse reports, and claim
  attempts per IP / per tag / per code. It's an in-memory limiter — correct for a
  single-process VPS; swap it for a shared store before running multiple instances.
- Short codes: 8 chars from an unambiguous 56-char alphabet (~2×10^14 space). Claim codes:
  `XXXX-XXXX-XXXX` from a disjoint uppercase-only 31-char alphabet.
- `MediaAsset` bytes are served from `/media/[id]` by unguessable cuid; the scan page decides
  whether to emit the `<img>` based on the photo visibility flag.

## Deployment (self-hosted VPS)

`Dockerfile` builds a standalone Next.js server; `docker-compose.yml` runs it with Postgres.

```bash
docker compose up -d --build
docker compose exec app npx prisma migrate deploy
docker compose exec app npm run db:seed
```

Set real `AUTH_SECRET`, `NEXTAUTH_URL`, `NEXT_PUBLIC_APP_URL`, `IP_HASH_SALT` (and
`PREMIUM_ENABLED` if wanted) in `.env` before deploying.
