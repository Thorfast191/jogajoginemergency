# Jogajog Emergency

Two connected products:

1. **Physical QR-sticker store** — customers browse physical products (bike, car, luggage,
   helmet stickers) and buy them with a **one-time payment**.
2. **SaaS emergency-profile platform** — the account, the emergency profile, the privacy
   controls, the themes, and the public page a finder or first responder lands on when they
   scan a tag.

A tag is *purchased*, not generated by the customer. QR codes come from a platform-controlled
inventory an admin mints in batches.

## The tier, and the line it must not cross

**Emergency information is free forever. Plus unlocks extras.**

| | Free | Plus |
|---|---|---|
| Name, photo, emergency message | ✅ | ✅ |
| Blood group, allergies, medical notes | ✅ | ✅ |
| Emergency contacts, message relay | ✅ | ✅ |
| Free themes | ✅ | ✅ |
| Portfolio (bio + links) | 🔒 | ✅ |
| Premium themes | 🔒 | ✅ |
| Scan history beyond the last 5 | 🔒 | ✅ |

A lapsed subscription must **never** hide medical data from a first responder. That is a
product-safety invariant, not a pricing preference. It is enforced in
`buildPublicProfileView` and asserted by a test that compares the emergency half of the DTO
entitled and unentitled. If you change the tier, that test is the thing to keep honest.

`src/lib/entitlements.ts` is the only place a `SubscriptionStatus` is interpreted.

## Themes

A `Theme` spans two surfaces: the artwork printed on a sticker (`Product.themeId`) and the
skin of the scan page (`Tag.themeId`). Buying a themed sticker sets that tag's look; a Plus
subscriber can re-skin any tag afterwards from the dashboard.

Themes are **character-agnostic by construction** — a theme is a name, a palette, a mascot key
and an artwork asset. Every seeded character is original. No licensed character is referenced
in code or seed data; if any are ever licensed, they are added as rows.

A premium skin on a lapsed account degrades to the default rather than breaking, and the tag
keeps its `themeId`, so re-subscribing restores the look.

## Stack

Next.js 16 (App Router; the proxy file is `src/proxy.ts`) + PostgreSQL + Prisma + Auth.js
(credentials, JWT sessions) + Tailwind v4 + `sharp`. Payments run through a `DEMO` provider
stub pending a real Bangladesh gateway (SSLCommerz / bKash). Tests: Vitest (`npm test`) —
security-critical pure logic only.

## Local setup

1. PostgreSQL 14+ with `DATABASE_URL` set in `.env`. `docker compose up -d postgres` spins one
   up with the wired-in credentials.
2. `npm install`
3. `npx prisma migrate deploy`
4. `npm run db:seed` — six themes, the Plus plan, an admin (`admin@jogajog.app` /
   `ChangeMe123!` — **change this immediately**), and four `ACTIVE` sticker products.
5. `npm run dev`

## Cart & checkout

The cart is an `httpOnly` `jj_cart` cookie holding `[{ slug, qty }]` and nothing else —
prices are always re-read from the database at checkout, so a tampered cookie cannot change
what anything costs. `parseCart` treats its input as entirely attacker-controlled: malformed
JSON yields an empty cart, quantities are clamped, duplicate slugs merge, and the line count
is capped.

Checkout allocates inventory tags with `SELECT … FOR UPDATE SKIP LOCKED` inside one
transaction, records an `ORDER` payment, marks the order `PAID`, and flips the tags to the
buyer as `ACTIVE` with the product's theme. `Order.idempotencyKey` is unique and minted
server-side per rendered form, so a double-submit returns the original order instead of
placing a second one.

## Tag lifecycle

```
UNASSIGNED  ──(admin batch generation)             raw inventory, no owner
ALLOCATED   ──(checkout reserves N of a product)   attached to an order, not yet active
ACTIVE      ──(order paid, or /claim by code)      owned and live
LOST / DEACTIVATED ──(owner, from the dashboard)
```

Each tag also carries a printed `claimCode` for attaching a sticker bought offline, gifted,
or replaced via `/claim`. Deleting a user detaches their tags (`onDelete: SetNull`).

## Privacy & security

- The public scan page renders **only** the DTO from `src/lib/public-profile.ts`. A field
  appears only if its per-field visibility flag is set. Presets (Minimal / Standard / Full)
  set the flags in one tap; any manual change makes the profile "Custom".
- Portfolio link URLs are restricted to `http(s)` in both the form schema and the DTO —
  `javascript:` and `data:` would be script execution in a finder's browser. Theme colours are
  restricted to hex literals because they reach the page inside a `style` attribute.
- `/media/[id]` authorizes every read (`src/lib/media-access.ts`). Product and theme art is
  public and immutable; a profile photo is served publicly only while a profile points at it
  with `photoPublic` set, and then as `private, max-age=300` so revocation cannot be defeated
  by a CDN's copy. Otherwise it needs the owner or an admin. Refusals 404 rather than 403.
- Raw finder IPs are never stored; `src/lib/hash.ts` salts and hashes them.
- Login is throttled failure-only, per-email (5/15min) with a loose per-IP net (30/15min) —
  loose because mobile carriers here NAT heavily. Signup is 5/hour per IP.
- A password reset stamps `User.passwordChangedAt`, and `requireActiveUser` rejects tokens
  minted before it, so a reset revokes outstanding JWT sessions.
- `src/lib/rate-limit.ts` is an **in-memory** limiter — correct for a single-process VPS.
  Swap it for a shared store before running multiple instances; it now guards credentials, so
  a second instance would give an attacker double the budget.
- Short codes: 8 chars from an unambiguous 56-char alphabet. Claim codes: `XXXX-XXXX-XXXX`
  from a disjoint uppercase-only 31-char alphabet.

## What's stubbed / next steps

- **Payments** — `DEMO` provider, marked succeeded immediately, for both orders and
  subscriptions. Implement an SSLCommerz/bKash checkout + webhook writing to the same
  `Payment` model, and let the webhook extend `Subscription.currentPeriodEnd`.
- **Subscription renewal** — there is no billing job. `activeSubscriptionStatus` compensates
  by checking `currentPeriodEnd` as well as status, so a stale `ACTIVE` row does not entitle.
- **Notifications** — `src/lib/notify.ts` logs to the console. Wire in email/SMS.
- **Scan geolocation** — `ScanEvent.approx*` columns exist but nothing populates them.
- **Theme artwork** — `Theme.artAssetId` exists; the admin form does not upload to it yet, and
  the store falls back to the product image.
- **Fulfilment** — `Order` has minimal nullable shipping fields and a `fulfillmentStatus`
  enum; no carrier integration.

## Deployment (self-hosted VPS)

`Dockerfile` builds a standalone Next.js server; `docker-compose.yml` runs it with Postgres.

```bash
docker compose up -d --build
docker compose exec app npx prisma migrate deploy
docker compose exec app npm run db:seed
```

Set real `AUTH_SECRET`, `NEXTAUTH_URL`, `NEXT_PUBLIC_APP_URL` and `IP_HASH_SALT` in `.env`
before deploying.
